# Database

Postgres — schema conventions, query patterns, and migration workflow.

## Conventions

- Table names: `snake_case`, plural (`users`, `note_links`)
- Primary keys: `uuid` generated by `gen_random_uuid()`
- Timestamps: `created_at`, `updated_at` on every table (trigger-managed)
- Soft deletes: `deleted_at` nullable timestamp; hard deletes only for PII on request

## Migration Workflow

We use plain SQL files in `db/migrations/`, numbered sequentially.

```
db/migrations/
├── 0001_create_users.sql
├── 0002_create_notes.sql
└── 0003_add_tags_index.sql
```

Run with `npm run migrate`. Never edit a committed migration — write a new one.

## Indexing Rules

1. Every foreign key gets an index automatically.
2. Columns used in `WHERE` clauses in hot paths get explicit indexes.
3. Profile before adding — indexes slow writes. See [[Performance]].

## Query Patterns

```sql
-- Always use parameterised queries (via pg)
const { rows } = await pool.query(
  'SELECT * FROM notes WHERE user_id = $1 AND deleted_at IS NULL',
  [userId]
)
```

No string interpolation into queries. Ever. See [[Backend]] for the validation layer that catches bad input before it reaches SQL.

## Backups

Automated daily snapshots via [[Deployment]]. Retention: 30 days. Test restores quarterly.
